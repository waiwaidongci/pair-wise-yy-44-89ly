# 巡演舞台调度与走位编排工作台

面向剧院巡演团队的舞台执行工作台，覆盖布景 / 机械区登记、演员走位自动绕障、执行提示、留言协同、版本回退、基线锁定和演出文档打印。

## 技术栈

Vue 3 + Element Plus + Pinia + Vue Router + TanStack Query + Axios + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62044`。

## 一套空间事实（核心模型）

舞台平面图、走位路线节点、执行提示和打印清单不再各画各的，全部读取
`src/spatial/` 这一份空间事实：

- `spatial/types.ts` — 区域（`StageArea`：占用范围 + 演员安全间隔 + 可选占用时间窗）、走位状态、冲突结构。
- `spatial/geometry.ts` — 线段与外扩安全间隔矩形求交、走位折线交叉计算。
- `spatial/pathfind.ts` — 50×50 网格 A*（八向、禁止切角）+ 拉线简化；**入场点与退场点不动，只重算中间节点**。
- `spatial/time.ts` — 时间码与“同一时段（时间窗重叠秒数）”判定。
- `spatial/validate.ts` — 唯一入口 `validateSpatial(cues, areas)`，范围一变全量重算，产出每条提示的状态：
  - `ok` 路线畅通；`rerouted` 已自动绕行；`blocked` 排不出来（说明**第几段路线跟哪块布景 / 哪条走位打架**）；`review` 旧提示缺范围数据，**保留原路线**待复核；`fixed` 机械动作 / 固定灯位不走演员路径。
- `spatial/collab.ts` — 区域级协同：两人同改一块区域时**先到者持锁生效**；离线改动回网后**按区域编号做 base/server/local 三方合并**，同字段冲突采用先提交者版本并列出冲突字段。

舞台平面图画布上：实色块＝物理占用，虚线框＝安全间隔，红叉＝同一时段走位交叉，
橙色虚线＝自动绕行后的生效路线，紫色虚线＝待复核的旧路线。

打印中心与画布同源：排不出来 / 待复核的走位整行标红，表首有禁用警示横幅，
未弄清前不得作为执行依据；CSV 同样带“空间状态 / 问题说明”两列。

## 核心工作流

1. 在“布景与机械区登记”表登记每块布景 / 机械区的占用范围、安全间隔（机械区可设占用时间窗）。
2. 范围一保存，所有时间窗内的走位立即重算绕行；受影响提示在页面横幅中逐条列出。
3. 旧版本导入的走位缺范围数据时保留原路线并标记“待复核”，核对后可一键转自动重算。
4. 同一时段两条走位交叉会在画布标红叉，并在提示与打印清单中写明冲突双方与重叠秒数。
5. 两人同改一块区域：先抢到区域锁的人生效，后来者提交被拒；“协同模拟”菜单可演示该场景。
6. 离线期间的区域修改进入待合并队列，回网后按区域编号三方合并，冲突字段采用先到者值。
7. 锁定演出基线，并从打印中心输出走位表和执行清单。

## 校验脚本

```bash
npm run check:spatial   # 绕障 / 交叉 / 时间窗 / 待复核 / 排不出来
npm run check:collab    # 先到先得锁 / 离线三方合并
```
